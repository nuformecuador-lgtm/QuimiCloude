## Recordatorio que va primero, no al final

`docs/verification.md` es explicito: **tocar `init.sh` o `scripts/` hace que el modo rapido no te
cubra**, y esta ficha toca los dos (`init.sh` bloque 6.c, `scripts/test-db.ts`,
`scripts/test-rapido.mjs` leido pero no tocado). Por tanto **T16 no es el veredicto de la feature**.
Lo que T16 demuestra es dos cosas acotadas:

1. `--rapido` **funciona** con el aislamiento puesto (arranca, crea base propia, no aborta), y
2. `--rapido` **no ensucia**: no deja ninguna base `qct_` de corrida detras.

**El veredicto real es T18** (`./init.sh` completo, que corre el leader). Nada de lo de abajo
autoriza a cerrar la feature.

## Como se lee el codigo de salida (sin trampas)

Cada corrida se redirige con `2>&1` a un fichero y `$?` se lee **inmediatamente despues**, nunca a
traves de una tuberia (`| tail` devolveria el estado de `tail`, es decir `0`, aunque el gate
fallara). Los ficheros se inspeccionaron con `grep`/`sed` y se **borraron al terminar**.

El inventario de bases se tomo con `pnpm run db:test list` **antes y despues** de cada corrida.

## Caso 1 — el diff SI toca algo con tests de integracion relacionados

### Como se provoco (honestamente, y que se deshizo)

El diff real de la rama **no arrastraba ningun test de integracion por si solo** (ver caso 2: solo
`.md`). Asi que se provoco el caso:

1. `cp lib/shared/db/prisma.ts _qc77_t16_prisma.bak` — copia de seguridad **antes** de tocar nada.
2. Se anadio **una linea de comentario** al final de `lib/shared/db/prisma.ts`:
   `// QC-77 T16: sonda temporal de seleccion del gate rapido. Se revierte al terminar.`
3. `git commit -q -m "tmp(QC-77 T16): sonda de seleccion, se revierte" -- lib/shared/db/prisma.ts`
   — **hizo falta un commit**: `test-rapido.mjs` calcula la seleccion con
   `git diff --name-only origin/dev...HEAD`, que solo ve lo **commiteado**. Un `touch` no habria
   cambiado el diff. Se commiteo **solo esa ruta** (`git commit -- <path>`), sin tocar el indice
   ni arrastrar el trabajo sin commitear de las tareas en paralelo.

`lib/shared/db/prisma.ts` es el archivo que T4 (caso C) ya tenia medido como uno que **si** arrastra
tests de integracion.

Diff resultante:

```
$ git diff --name-only origin/dev...HEAD
lib/shared/db/prisma.ts
specs/.../design.md
specs/.../requirements.md
specs/.../tasks.md
```

**Deshecho al terminar:** `git reset --mixed HEAD~1` (el commit temporal desaparece) +
`cp _qc77_t16_prisma.bak lib/shared/db/prisma.ts` (**restauracion desde copia, NO
`git checkout`**, como exige `docs/verification.md > Cuando lo que verificas es el gate mismo`: el
arbol tiene cambios sin commitear de otras tareas). Comprobado despues:
`git log --oneline -1` → `fedcbf6` (el commit del spec, el de antes), y
`git diff --stat lib/shared/db/prisma.ts` → **vacio**.

## Divergencias que hay que decir

1. **El caso 1 necesito dos intentos.** El primero salio en **1** por dos timeouts de UI ajenos a la
   feature (QC-58). Queda dicho tal cual: la ficha pedia «exit 0» y la primera corrida no lo dio.
   Lo que si es firme es que **ninguna de las dos corridas dejo base sucia**, ni la roja.
2. **Un rojo en la primera mitad se come las guardias.** `test-rapido.mjs` las corre solo si la
   seleccion por diff salio verde. No es un defecto de QC-77 —es el diseno de `test-rapido.mjs`, que
   no toca esta feature— pero conviene saberlo: «el gate rapido corre siempre todas las guardias»
   es cierto **hasta el primer rojo**.
3. **El coste de tocar `prisma.ts` es la suite casi entera**: `related` selecciono **146** archivos
   y la corrida tardo **~11 min**. El modo rapido deja de ser rapido cuando el diff toca un punto
   unico de importacion. Tampoco es de QC-77; es contexto para quien lea los tiempos.
